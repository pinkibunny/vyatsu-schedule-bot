# Бот расписания ВК

Отдельный Worker для сообщества https://vk.ru/club242581427.
Показывает расписание группы БТб-3101-03-00 из общего JSON с Telegram-ботом.
Поддерживает сегодня, завтра, послезавтра, текущую и следующую недели,
календарь опубликованных дат, подгруппы и состояние загрузки данных.
Кнопки передают выбранную подгруппу в payload: хранить профили пользователей
или переписку в базе данных не требуется. Для текстовых команд бот сначала
предлагает выбрать подгруппу. Можно также ввести дату `26.10.2026`.
Telegram Worker в каталоге `worker` продолжает работать отдельно.

Форматирование, объединение занятий по времени, фильтр подгрупп,
календарь и загрузчик с резервной копией используются из `../worker/src`.
GitHub Actions продолжает обновлять общее расписание каждый час.
Данные кешируются на 60 секунд, при сбое источника используется сохранённая
копия и показывается предупреждение.

«Отзыв / идея» ведёт к существующему анонимному сценарию в Telegram.
В диалогах сообщества ВК администраторы видят отправителя: аналогичную
анонимность внутри переписки сообщества обещать нельзя.

## Развёртывание через Cloudflare

1. Workers & Pages → Create application → Connect GitHub.
2. Выбрать `pinkibunny/vyatsu-schedule-bot`, ветку `main`.
3. Имя проекта: `vyatsu-schedule-vk-bot`.
4. Build command: `npm test`.
5. Deploy command: `npx wrangler@4 deploy`.
6. В Advanced settings указать Path / Root directory: `vk-worker`.
7. Отключить сборки для непроизводственных веток и развернуть Worker.

## Настройки сообщества

В Управление → Работа с API → Ключи доступа создать ключ сообщества
с правом работы с сообщениями. Личные пользовательские токены не нужны.

В Работа с API → Callback API создать сервер. После развёртывания
адрес сервера — URL нового Worker с окончанием `/vk`.
Скопировать строку, которую сервер должен вернуть для подтверждения.
Придумать случайный секрет и указать его в поле «Секретный ключ».

В Cloudflare → новый Worker → Settings → Variables and Secrets добавить:

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | `VK_TOKEN` | Ключ доступа сообщества с правом работы с сообщениями |
| Secret | `VK_CALLBACK_SECRET` | Тот же секретный ключ, что в Callback API |
| Secret | `VK_CONFIRMATION_CODE` | Строка подтверждения из Callback API |

Сохранить и развернуть версию с секретами. Убедиться, что она активна
и получает 100% трафика. ID сообщества `242581427` уже указан в конфигурации.
Не публиковать токен или секрет в репозитории, переписке и на скриншотах.

`GET /health` проверяет наличие настроек, но не соединение с ВК.
После добавления всех значений должен отвечать JSON с `ok: true`.

В ВК подтвердить сервер и включить событие «Входящее сообщение»
(`message_new`). Long Poll для этого Worker не используется.

Написать сообществу «начать», выбрать подгруппу и запросить расписание.
Команда «тест» по-прежнему отвечает проверкой связи и открывает меню.
Ответ подтверждает доставку ВК → Cloudflare → ВК. Повторить проверку
в разное время, прежде чем считать соединение устойчивым.

При ошибке доставки Worker возвращает HTTP 502, чтобы ВК мог повторить событие.
Для повторной доставки одного сообщения используется тот же `random_id`,
чтобы не плодить одинаковые ответы. Содержимое сообщений и данные отправителя
не записываются в прикладные логи.

В прикладных логах записываются только длительности загрузки расписания
(`schedule_ms`) и отправки ответа (`send_ms`), номер части и использование
резервной копии. Эти измерения помогают отделить задержку GitHub от API ВК.

При обновлении уже работающего Worker заново создавать сервер Callback API
или добавлять секреты не требуется. После автоматического развёртывания
`GET /health` показывает `stage: "schedule"`.

## Локальные тесты

Нужен Node.js 22 или новее. Дополнительные пакеты для тестов не нужны.

```bash
npm --prefix vk-worker test
```
