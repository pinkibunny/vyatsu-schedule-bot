# Закрытая статистика Telegram-бота

## Что хранится

Таблица `stats_users`: Telegram ID, актуальные имя, фамилия и username из профиля,
даты первого и последнего обращения. Таблица `stats_events`: уникальный update_id,
Telegram ID отправителя, московская дата, время получения события и признак
запроса расписания. Тексты сообщений, содержимое ответов и полные Telegram
обновления в базу не записываются. Логи не содержат профили пользователей.

Учитываются личные сообщения и нажатия callback-кнопок. Одно входящее событие —
одно взаимодействие. Запрос расписания учитывается при нажатии «Сегодня»,
«Завтра», «Послезавтра», недели или конкретной даты. Меню и выбор подгруппы
учитываются только как взаимодействия. Это счётчики запросов, не подтверждения
успешной выдачи расписания. Повторная доставка update_id не увеличивает числа.

Чтение старых сообщений, переходы по URL-кнопке «ВК версия», команды статистики,
групповые чаты и прежний анонимный сценарий отзывов не учитываются.
Прошлые обращения до подключения базы восстановить нельзя.

Учёт выполняется параллельно обычному ответу через `waitUntil`.
HTTP webhook и выдача расписания не ждут D1. При сбое базы теряется только
запись статистики: ответ бота продолжается. Пропущенные при сбое события
не восстанавливаются автоматически; отчёты могут отставать на время записи.

## Доступ владельца

- `/stats`: уникальные и активные пользователи, взаимодействия за сегодня,
  7/30 дней и всё время, запросы расписания. Обращения владельца отдельно.
- `/users`: список остальных пользователей по активности, по пять на страницу;
  имя, username, ID, взаимодействия, запросы расписания, первое/последнее
  обращение. Навигация кнопками или `/users 2`.

Доступ только в личном чате владельца: проверяются и ID отправителя, и ID чата.
Владелец задаётся положительным Telegram ID в секрете `STATS_ADMIN_ID`.
Если его нет, используется существующий `ADMIN_CHAT_ID`, но только если это
положительный ID личного аккаунта, а не отрицательный ID группы.
Не следует добавлять административные команды в публичное меню BotFather.

Периоды — московские календарные дни, включая сегодня. Для 7 дней берутся
сегодня и шесть предыдущих дней; для 30 — сегодня и 29 предыдущих.

## Подключение

1. В Cloudflare открыть Storage & databases → D1 → Create database.
2. Название: `vyatsu-bot-stats`. Создать базу; таблицы вручную создавать не надо.
3. Скопировать Database ID (UUID). Это идентификатор базы, не пароль и не токен.
4. Зафиксировать привязку в `worker/wrangler.jsonc`:

```json
"d1_databases": [{
  "binding": "STATS_DB",
  "database_name": "vyatsu-bot-stats",
  "database_id": "UUID СОЗДАННОЙ БАЗЫ"
}]
```

Не коммитить подставной UUID. Конфигурация добавляется после создания базы.
Привязку следует хранить в Wrangler, иначе последующее развёртывание может
перезаписать настройку, сделанную только через Cloudflare Dashboard.
При запросе Cloudflare предоставить токену сборки необходимые права на D1;
при отказе доступа не менять токены других проектов.

После автоматического развёртывания таблицы и индексы создадутся при первом
учитываемом обращении или административной команде. До привязки базы бот
работает как раньше, а владелец получает через `/stats` инструкцию подключения.

Проверка: `/myid` и кнопка расписания, затем `/stats` и `/users` от владельца.
`/stats` сам по себе в счётчик не попадает. В `/health` публикуется только
наличие привязки и настройки владельца, без пользовательских данных.

Остановка учёта: секрет `STATS_ENABLED` со значением `false`
(секрет сохранится при следующих развёртываниях Wrangler).
Данные при этом сохраняются. Для окончательной очистки требуется отдельно
удалить таблицы/базу; код не выполняет автоматическое удаление.
